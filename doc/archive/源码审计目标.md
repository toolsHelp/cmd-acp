这个协议设计是整个方案的核心。目标不是简单让 `cmdc → cmd-acp` 通信，而是设计一个**通用 Permission Broker Protocol**：

* `command-code` 不知道 ACP 存在
* `cmd-acp` 不知道具体工具权限逻辑
* ACP Client（Paseo/Zed）只负责 UI 决策
* 中间通过 broker 完成同步阻塞授权

最终形成：

```text
command-code
    |
    | Permission Request
    |
    v
Permission Broker
    |
    | ACP request_permission
    |
    v
ACP Client

    用户 Allow/Deny

    ^
    |
Permission Response
    |
command-code继续执行
```

---

# 1. 设计原则

## 核心原则

### 1. request 必须可恢复

因为：

```
command-code
      |
      等待
      |
用户30秒后点击
```

所以必须有：

```
requestId
```

不能依赖连接顺序。

---

### 2. request 必须绑定 session

否则：

```
Session A:

删除文件


Session B:

执行shell
```

两个请求同时回来会串。

所以：

```
sessionId
+
requestId
```

双 key。

---

### 3. response 必须幂等

用户可能：

* 双击允许
* UI 重发
* 网络重连

所以：

同一个：

```
requestId
```

只能有一个最终状态。

---

# 2. Broker Transport

先定义传输无关协议。

比如：

```
Pipe
Socket
HTTP
stdio
```

都只负责传：

```
JSON message
```

协议：

```
Permission Broker Protocol v1
```

```json
     "canRemember": true,
```

# 4. 字段解释

## requestId

格式：

```
req_<uuid>
```

例如：

```
req_01J8X9ABCD
```

生命周期：

```
create
 |
 |
pending
 |
 +---- allow
 |
 +---- deny
 |
 +---- timeout
```

永不复用。

---

## sessionId

来自：

```
ACP session/new
```

例如：

```
sess_123456
```

映射：

```
ACP session
        |
        |
Command Code -- session
```

---

## tool.name

不要限制：

目前：

```
shell_command
edit_file
write_file
```

未来：

```
browser
database
git
docker
```

所以：

```
string
```

而不是 enum。

---

## risk

建议：

```
low
medium
high
critical
```

例如：

| 工具            | 风险       |
| ------------- | -------- |
| read_file     | low      |
| edit_file     | medium   |
| shell_command | high     |
| rm -rf        | critical |

UI 可以直接展示。

# 5. Response Schema

broker → command-code

允许：

```json
{
 "type":"permission_response",

 "version":"1.0",

 "requestId":"req_01J8X9ABCD",

 "sessionId":"sess_8f31d2",


 "decision":{

    "result":"allow",

    "scope":"once"
 },


 "timestamp":1789000010000
}
```

拒绝：

```json
{
 "decision":{

    "result":"deny",

    "reason":
      "User rejected request",

    "scope":"once"
 }
}
```

---

# 6. Decision 枚举

不要设计：

```
true/false
```

未来扩展不了。

定义：

```typescript
enum PermissionResult {

 Allow = "allow",

 Deny = "deny",

 Timeout = "timeout",

 Cancelled = "cancelled"

}
```

---

# 7. Scope 设计

这个非常重要。

不要只有一次。

设计：

```typescript
enum PermissionScope {

 Once =
 "once",

 Session =
 "session",

 Always =
 "always"

}
```

例如：

用户：

```
允许 npm install
```

可以：

```
session
```

避免每次弹。


```typescript
   resolve
```

---

## Step 5

```

```

显示：

```

```

```

```

返回：

```

```

```typescript

})
```

## Step 8

```

```

# 15. 一个关键调整

你的目标不要定义成：

> “给 Command Code 增加 ACP 支持”

这个官方已经有。

应该定义成：

> **“为 headless coding agent 增加可插拔 human-in-the-loop permission broker”**

这个抽象层次更高。

这样：

未来：

```
Command Code
Claude Code
OpenCode
Aider
```

都可以复用。

下一步建议继续做 **`cmd-acp 端具体代码改造设计`**：

即：

```
agent.ts
sessions.ts
cmd-runner.ts

具体增加哪些 class / interface / 方法
```

这样可以直接进入 fork 开发。
